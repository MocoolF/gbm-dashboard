# GBM Studio — дашборд агентства

Статический дашборд: HTML + CSS + JS, без сборки и без бэкенда.
Данные лежат в репозитории в JSON — обновляются коммитом.

## Запуск локально
```bash
cd ~/Documents/gbm-dashboard
python3 -m http.server 8777
# открыть http://localhost:8777
```
Через `file://` не откроется — браузер блокирует чтение JSON.

## Структура
```
index.html          разметка
assets/style.css    стили (светлая + тёмная тема)
assets/app.js       расчёты и отрисовка
data/leads.json     заявки — одна строка = одна заявка
data/spend.json     расходы — канал × дата × сумма
data/goals.json     цели по месяцам
data/channels.json  справочник каналов, услуг, шагов воронки
```

## Формат данных

### `data/leads.json`
Одна запись на заявку. Даты в формате `YYYY-MM-DD`, пустое значение — `null`.

```json
{
  "id": "L0162",
  "date": "2026-10-06",        // дата первичной заявки
  "channel": "avito",          // id из channels.json
  "service": "maps",           // услуга, за которой пришли
  "name": "Шиномонтаж на Мира",
  "qual": true,
  "qual_date": "2026-10-06",   // когда признали квалом
  "zoom_set_date": "2026-10-07", // когда назначили зум
  "zoom_date": "2026-10-09",   // когда зум реально прошёл
  "offer_date": null,          // когда отправили КП
  "won_date": null,            // когда оплатили
  "amount": 0,                 // сумма сделки, ₽ (ставится вместе с won_date)
  "status": "zoom",            // new | qual | zoom_set | zoom | offer | won | lost
  "lost_reason": null,
  "note": ""
}
```

**Правило:** заполняются только те даты, события по которым реально произошли.
Статус — последний достигнутый шаг. Воронка и конверсии считаются из дат, а не из статуса.
Поля `zoom_set_date` и `offer_date` на листе «Сводка» не отображаются, но заполнять их стоит —
они понадобятся для разбора узких мест на листе «Каналы».

### `data/spend.json`
```json
{ "date": "2026-10-06", "channel": "avito", "amount": 1200 }
```
Одна строка на канал в день. Канал без рекламного бюджета (партнёры, сарафан) просто не пишем.

### `data/goals.json`
```json
{ "2026-10": { "leads": 100, "zooms": 15 } }
```

## Как считаются метрики

| Метрика | Логика |
|---|---|
| Бюджет | сумма `spend` за период по выбранным каналам (точной цифрой, верхний ряд) |
| Стоимость первичной заявки | бюджет ÷ заявки за период |
| Заявки | заявки с `date` внутри периода |
| Квал. заявки | из тех же заявок — у кого есть `qual_date` (когортно) |
| Цена квала | бюджет ÷ квал. заявки |
| Зумы | зумы, **проведённые** в периоде (`zoom_date` внутри периода) |
| Продажи / Выручка | оплаты с `won_date` внутри периода |
| Воронка | **когорта**: заявки периода и то, куда они дошли на сегодня. Показывает 4 шага — заявки → квал → проведённый зум → продажа, только количества |
| Конверсии (кольца) | переходы между теми же шагами + итоговая заявка → продажа |
| Прогноз цели | факт ÷ прошедшие дни × дней в месяце |

Зумы и продажи считаются **по событию** (что реально случилось в периоде), воронка —
**по когорте** (что стало с заявками этого периода). Это разные вопросы, поэтому цифры
зумов в плитке и в воронке могут отличаться — так и задумано.

## Деплой на GitHub Pages
```bash
git remote add origin git@github.com:<аккаунт>/gbm-dashboard.git
git push -u origin main
```
Затем в репозитории: **Settings → Pages → Source: Deploy from a branch → main / (root)**.

Поддомен: в `Settings → Pages → Custom domain` указать `dash.gbmstudio.ru`,
у регистратора домена добавить CNAME-запись `dash` → `<аккаунт>.github.io`.

⚠️ **Приватность:** на публичном репозитории данные о выручке и продажах доступны всем
по прямой ссылке. Варианты: приватный репозиторий + GitHub Pro, либо выкладывать
на свой сервер за basic-auth.

## Обновление данных
Внести строки в `data/*.json` → `git commit` → `git push`. Pages пересоберётся за минуту.
